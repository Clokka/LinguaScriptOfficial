Plan, in order

  1. Section registry. Turn the favourites (Subtitle cinema, Kinetic headline, Word marquee, Platform launcher, Cover-flow, Deck fan, Progress bento, Gold strip, Phone + widget…) into React components with the same props. One file lists them all.
  2. Config renderer. A page that takes a config (theme + list of sections) and draws it. Heavy sections load lazily so the first load stays small.
  3. Admin tab. This builder, inside your real Admin page: preview, save, publish.
  4. Experiment wiring. landing_page_v3 arms = saved config IDs. Keep 2 arms until you have the traffic for more.
  5. Brand loader. The decoding "LinguaScript" loader as one component for page loads and the 10–30 s subtitle wait.

Rules so it doesn't break things

  • Speed: sections load only when used; three.js and PostHog stay out of the first load (your AGENTS.md rule).
  • Save visitors' data: the builder, previews and loader lab live only behind the admin login and load lazily. A visitor downloads just the one published version and the sections it uses, never the other 21 designs.
  • Honest numbers: mock-up numbers (1,204 words, 12 days) are samples. On the live site, show real data or none.
  • One change at a time: test a theme or a hero, not both, or you won't know what worked.
  • Accessibility: every animation stops when the phone asks for reduced motion; word colours always have a second clue (rings or labels).
  • SEO: all arms keep the same main heading topic and one canonical URL, so Google sees one page.
