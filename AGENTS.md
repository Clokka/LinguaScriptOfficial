
- Verb/word form checks use public.word_forms (UniMorph import + cached analyze-word-form AI results) and sentence_patterns.slots[0].accepts — never suffix heuristics. Why: irregular forms and non-hand-coded languages need exact data.
- UI translation uses the lightweight `src/i18n` (useT, STRINGS) keyed by profile native_language > device choice > browser language; why: reassure non-English beginners without a heavy i18n dependency.
- Vocabulary-coverage thresholds (98 ideal / 95 min / 90 stretch) live only in src/lib/coverage.ts; why: one comprehensible-input rule across recommendations, labels and rails.
- Untranslated UI text is machine-translated at runtime by src/i18n/AutoTranslate (translate-ui function, cached per language on device); mark learning-language text translate="no". Why: switching native language must change the whole app without hand-translating every screen.
- Website and extension images (logos, mascot, icons, illustrations) are SVG; the chameleon comes from public/logo.svg / favicon.svg (same art as ChameleonMascot). PNG/ICO only where a platform requires it (favicon.ico, apple-touch, Chrome manifest icons), rendered from the SVG — never upscaled from a small PNG. Why: the blurry favicon PNG made the logo and extension icons fuzzy.
- Reviews follow ONE ladder everywhere: a word that turns green goes GOLD 5 minutes later (interval_days 0, timed from state_changed_at), then after 1, 3, 7, 14, 30 days, then ×1.5 forever. Tapping gold in a video only turns it green on screen (green_revealed_at); only a flashcard review moves it up the ladder. Lives ONLY in packages/core/src/review.ts (website imports it via the `@linguascript/core` alias; src/lib/vocab.ts re-exports it); the extension's `deckState()` in extension/background.js is checked against it by `npm run test:review`. Why: one schedule the learner can see, on web, phone and extension.
- Write (/write) and Speak (/speak) are hidden from all menus for now (direct URL only); keep the app to watching until the redesign. The extension's any-website reader is Alt+L only.
- Analytics: every PostHog event goes through src/lib/analytics.ts (`track`, `trackOnce`, `setPerson`) with snake_case past-tense names from the `AnalyticsEvent` list; never call posthog.capture directly. Why: one funnel with consistent names.
- The Chameleon Method has three pillars (after Kató Lomb): 📖🎬 read + watch (player, extension reader on any site), ✍️ write (/write, LinguaScripts from 1–2 red + green words in the learner's hobby, `linguascript-write` function), 🗣️ speak (/speak, 1/2/3-minute challenge). Using a red word correctly in writing or speech counts as a correct review. Why: input alone doesn't make words active.
- Android "select text → LinguaScript": mobile/plugins/withProcessText.js adds a native card (ProcessTextActivity.kt) that translates the selection and queues Save into files/ls-inbox.json; app/index.tsx hands the inbox to the site, src/components/AppInbox.tsx saves to the red deck. Why: tap-to-save from any app with no special permission.
- Word meanings: dictionary first (public.word_dictionary — top 10,000 words per language seeded by the seed-dictionary function from the Admin page, plus every word looked up before), then Google (official API when GOOGLE_TRANSLATE_API_KEY is set, else the free endpoint), then AI only when Google echoes the word; AI enriches lemma/IPA in the background. Why: taps and flashcards must get a real meaning fast.
- Word style is a learner choice (extension pop-up "Colour | Rings", chrome.storage ls_style, html.ls-style-ring): Colour recolours the real word (deeper shades on light backgrounds via .ls-light in the reader; gold = moving glimmer), Rings draws a deck-coloured circle (gold pulses). Why: both looks are wanted until one clearly wins; delete the loser then.
- Android 🦎 bubble: mobile/plugins/withWordBubble.js + word-bubble/*.kt. Tap → one screen capture (MediaProjection, consent each time) → ML Kit on the phone → WordOverlayView draws Colour (word redrawn in system font, own background patch, gold glimmer; busy backgrounds fall back to a ring) or Rings. Deck comes from files/ls-deck.json written by the site (AppInbox "deck" message); on/off from the Profile switch via linguascriptbubble:// links. Why: tap-to-colour works in any app without the accessibility permission Google rejects.
- Shared code for every app (website, Expo app, future apps) lives in packages/core: pure rules in review.ts, website↔app WebView messages in bridge.ts, database helpers in vocab.ts etc. The website imports it through the `@linguascript/core` alias (vite.config.ts, tsconfig, remotion.config.ts); the website itself stays at the repo root because Lovable syncs from there. Copy src/integrations/supabase/types.ts to packages/core/src/database.types.ts when migrations change tables. Why: one copy of each rule, so the apps never disagree.
- The new Expo app plan, what it must keep (package uk.co.LinguaScript.app, EAS project id, plugins) and the build prompt: docs/MOBILE_REBUILD.md.
- 📷 Scan a page: photo of a printed page → `scan-page` function (Gemini vision via aiChat) finds the words the learner MARKED: pen circle/underline → red; highlighter red/pink → red, orange/yellow → orange, green → green. The learner sees the list first (ScanPageButton on /flashcards), then `saveScannedWords` in packages/core/src/vocab.ts saves them (existing words only move forward). Why: words circled in a real book go straight into the decks.
- PostHog and Clarity load only after the visitor accepts analytics in the cookie banner (src/lib/consent.ts); add any new tracker behind the same consent. Why: UK GDPR/PECR require consent before non-essential cookies.
- 🎬 Video Studio (/studio, direct URL only): record with the camera (live deck-coloured words via speech recognition) or pick a video; `transcribe-audio` (Gemini via aiChat) turns ~30 s 16 kHz WAV clips cut in the browser into timed lines + translations; src/lib/videoStudio.ts `drawCaption` paints preview AND the final MediaRecorder render, so what you see is what gets posted. Why: learners post their own speaking videos with LinguaScript dual subtitles, and the video never has to be uploaded.
- Speed: keep the first-load bundle small. three.js / model-viewer / PostHog never go in it: import heavy things only with `import()` (a plain `import { x }` from a 3D file drags all of three in — XpToast did, +600 kB), model-viewer via `ensureModelViewer()` (src/lib/modelViewer.ts), PostHog via src/lib/posthog.ts (`withPosthog`, loaded after consent + idle). `useAuth` is one shared store, so pages don't start in "loading" again. Check with `npx vite build`: the entry `index-*.js` was 1.74 MB, now ~0.8 MB. Why: black screen + green spinner on every page.
- Hobby search candidates rank by verified audience statistics before transcript coverage scoring; never append CEFR teaching keywords to hobby searches. Why: authentic interests determine content, vocabulary coverage determines suitability.
- Route and auth initialization render PageLoading instead of null or spinner-only screens. Why: slow networks must retain a visible application shell.
- Store prefilled YouTube hobby candidates in public.hobby_video_catalog, separate from caption-ready films; populate with scripts/seed-hobby-catalog.ts using server credentials only. Why: real metadata is not proof of available subtitles or learner suitability.
- MCP (ChatGPT / Claude connector): tools live in src/lib/mcp/tools, one per file; `npx vite build` regenerates supabase/functions/mcp/index.ts (never hand-edit it). Reviews go through packages/core/src/review.ts (`promote` + `applySrsReview`), same as flashcards. How to connect: docs/MCP.md. Why: learners already study in ChatGPT/Claude — the AI should teach frequent words and quiz their own decks.
- Android bubble taps work on ANY word it reads (not just deck words), so YouTube subtitles are tappable from the first video. Netflix/Disney+ mark the screen secure: screenshots are black, the bubble says so. Highlight-to-save is the PROCESS_TEXT "Save to LinguaScript" menu item — always on in any app, no overlay permission. Why: one tap from any subtitle or text to a flashcard.
