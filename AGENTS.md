
- Verb/word form checks use public.word_forms (UniMorph import + cached analyze-word-form AI results) and sentence_patterns.slots[0].accepts — never suffix heuristics. Why: irregular forms and non-hand-coded languages need exact data.
- UI translation uses the lightweight `src/i18n` (useT, STRINGS) keyed by profile native_language > device choice > browser language; why: reassure non-English beginners without a heavy i18n dependency.
- Vocabulary-coverage thresholds (98 ideal / 95 min / 90 stretch) live only in src/lib/coverage.ts; why: one comprehensible-input rule across recommendations, labels and rails.
- Untranslated UI text is machine-translated at runtime by src/i18n/AutoTranslate (translate-ui function, cached per language on device); mark learning-language text translate="no". Why: switching native language must change the whole app without hand-translating every screen.
- Website and extension images (logos, mascot, icons, illustrations) are SVG; the chameleon comes from public/logo.svg / favicon.svg (same art as ChameleonMascot). PNG/ICO only where a platform requires it (favicon.ico, apple-touch, Chrome manifest icons), rendered from the SVG — never upscaled from a small PNG. Why: the blurry favicon PNG made the logo and extension icons fuzzy.
- Reviews follow ONE ladder everywhere: a word that turns green goes GOLD 5 minutes later (interval_days 0, timed from state_changed_at), then after 1, 3, 7, 14, 30 days, then ×1.5 forever. Tapping gold in a video only turns it green on screen (green_revealed_at); only a flashcard review moves it up the ladder. Lives in `nextReviewInterval` / `isDueGold` (src/lib/vocab.ts + packages/core/src/vocab.ts, kept identical) and `deckState()` in extension/background.js. Why: one schedule the learner can see, on web, phone and extension.
- Write (/write) and Speak (/speak) are hidden from all menus for now (direct URL only); keep the app to watching until the redesign. The extension's any-website reader is Alt+L only.
- Analytics: every PostHog event goes through src/lib/analytics.ts (`track`, `trackOnce`, `setPerson`) with snake_case past-tense names from the `AnalyticsEvent` list; never call posthog.capture directly. Why: one funnel with consistent names.
- The Chameleon Method has three pillars (after Kató Lomb): 📖🎬 read + watch (player, extension reader on any site), ✍️ write (/write, LinguaScripts from 1–2 red + green words in the learner's hobby, `linguascript-write` function), 🗣️ speak (/speak, 1/2/3-minute challenge). Using a red word correctly in writing or speech counts as a correct review. Why: input alone doesn't make words active.
- Android "select text → LinguaScript": mobile/plugins/withProcessText.js adds a native card (ProcessTextActivity.kt) that translates the selection and queues Save into files/ls-inbox.json; app/index.tsx hands the inbox to the site, src/components/AppInbox.tsx saves to the red deck. Why: tap-to-save from any app with no special permission.
- Word meanings: dictionary first (public.word_dictionary — top 10,000 words per language seeded by the seed-dictionary function from the Admin page, plus every word looked up before), then Google (official API when GOOGLE_TRANSLATE_API_KEY is set, else the free endpoint), then AI only when Google echoes the word; AI enriches lemma/IPA in the background. Why: taps and flashcards must get a real meaning fast.
- Word style is a learner choice (extension pop-up "Colour | Rings", chrome.storage ls_style, html.ls-style-ring): Colour recolours the real word (deeper shades on light backgrounds via .ls-light in the reader; gold = moving glimmer), Rings draws a deck-coloured circle (gold pulses). Why: both looks are wanted until one clearly wins; delete the loser then.
